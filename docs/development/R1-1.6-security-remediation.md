## 修复选择

采用路线 B，使用 Spring Boot 4.0.9 的 BOM 统一解析 Spring Framework 7.0.10。官方支持 Java 21、Maven 3.6.3+、Jakarta Servlet 6.1。项目仍使用 Maven Wrapper 3.9.16。路线 A 的修复需要企业分发渠道，现有可公开复现的 GitHub Actions 无此渠道。路线 C 无需采用，OSV 检查、退出码与分支保护保持原样。 [Boot 4.0 系统要求](https://docs.spring.io/spring-boot/4.0/system-requirements.html) · [官方迁移指南](https://github.com/spring-projects/spring-boot/wiki/Spring-Boot-4.0-Migration-Guide)

变更限定为 BOM 和必要的兼容调整。WebMVC、Flyway 使用相应启动器，Actuator 与 Security 自动配置跟随新包名，错误 JSON 使用 Boot 4 默认 Jackson 3。真实 HTTP 测试使用 Boot 4 的 TestRestTemplate 与 Testcontainers 2 PostgreSQL 模块。移除 Boot 3 下的旧补丁覆盖，让 BOM 管理相应依赖。Flyway 迁移脚本、权限逻辑、Compose 与 CI 工作流不变。未来 Runtime 集成库需要验证对 Framework 7 与 Jackson 3 的兼容性。
