# 第 3 轮评测：最终答案一致性校验与提示词 v4 系列

2026-11-24，分支 `feat/r3-final-consistency`。模型 gpt-4o-mini（温度 0.1），research 预算 24000 token / 8 轮，`survey_get_stats` v2（带投票数据），dev v3（35 个调研案例 + 10 个对抗案例），repeats=3，探针 C04 / C32 / C35 各 5 次，每个 step 141 个 Run。数据集是模拟数据。

> **注意：本轮所有建议正确率都基于规则版观点抽取器（v0，macro-F1 约 0.08）**，和第 2 轮一样。

**结论**：
- **默认提示词保持 v2，第 3 轮不采用 v4 系列。** v4.2（最后一版）在 step 1c 没有通过必须满足的验收线：hold_sparse 相对 step 0 降了 7 个（13 → 6），超过"降幅不超过 4"。按事先约定，不再修订，step 2（开启一致性校验）没有跑。
- 因为最终版本仍是 v2（第 2 轮已在 test 集上评测过），**本轮没有打开 test 集**，test 集保持冻结。
- 一致性校验（`craftpilot.runtime.final-consistency-check`）已合入并有测试，默认关闭；**它从未在真实模型上评测过**，因为 v2 不输出它检查的 `pollReadings` / `concerns`（第 7 节）。
- v4.2（V12）**已评估，未采用：hold_sparse 13→6**；作为负面结果保留在迁移里。
- 三条经验（第 6 节）：输出格式陷阱、concerns 计数粒度的影响、规则优先级没被模型遵守。

## 5. 为什么 step 1c 不通过

hold_sparse 的 9 次失败**全部是没跑完**（4 次 MAX_TURNS、5 次 TOKEN_BUDGET），不是判错：跑完的 6 个 Run 全对（step 0 是 13/13、step 1b 是 12/12）。v4 系列让 Agent 做更多次 `evidence_search`（平均工具调用 8.2 → 9.7 → 11.3，p95 10 → 14），证据稀少的案例里模型一直搜，直到耗尽 8 轮或 24000 token。v4.2 要求按属性计人数，进一步加重了这一点（C08、C16、C17、C19、C20、C28、C31 都是 14–16 次工具调用后停止）。

也就是说，v4.2 的判断规则在完成的 Run 上不差（82/93），但它和当前的轮数 / token 预算不兼容。修这个需要改预算、给模型"剩余轮数"提示，或改提示词里的搜索指引，都超出了本轮约定的范围。

## 6. 三条经验

1. **输出格式陷阱**："Before deciding, write down the numbers"（先写下数字）加上用列表描述最终字段，会诱导 mini 先写一份带标题的 Markdown 报告，而不是一个 JSON 对象；首尾大括号截取拿到的是两条投票读数，解析失败（step 1：41/111）。只改这两处措辞（"给最终答案时填这些字段" + "只输出一个 JSON 对象，不要 Markdown，理由写进 summary"）就降到 0/28、0/111。**教训：提示词里任何"先写 / 先列出"的步骤都可能被当成一次单独的输出；最终格式要求要放在开头并说死。**
2. **concerns 计数粒度决定判断**：v4 / v4.1 按具体问题列 concerns，C07 的"线头 / 走线 / 边油"变成三条各 1 人，"两人以上才算缺陷"的规则随之失效，判 HOLD（0/3）；v4.2 按属性分组后 C07 3/3，C35 的 mentionedBy 也从夸大的 2–3 回到 1。但分组同时让 mentionedBy 整体变小（=1 的从 42 增到 55），并让 Agent 为了按属性计人数而多搜索，耗尽预算（第 5 节）。**教训：计数单位是规则的一部分，改它等于改判断阈值，要整体评估。**
3. **规则优先级没被模型遵守**：v4 / v4.1 的 REVISE 规则已写明"优先于购买意向和对立投票"，规则也按顺序排列、写了"stop at the first that applies"，C06（袖长 mentionedBy 4、投票 5:6）仍 3/3 判 HOLD (split)；v4.2 在 REVISE 规则里再明确一句后是 2/3。同样，v4 的"一个人的小瑕疵不推翻会买多数"在 C35 上没有生效，因为模型先把人数夸大成 2–3。**教训：mini 不可靠地执行有序规则表；靠措辞强调只能部分修正，需要结构化字段 + 代码校验（如一致性校验）或在代码里做决策。**

## 7. 一致性校验的状态

最终答案一致性校验（`FinalConsistencyCheck`，`craftpilot.runtime.final-consistency-check`）的代码、迁移（V9）、指标和测试都已合入，**默认关闭，没有在真实模型上评测过**。原因：校验只检查结构化字段 `pollReadings` 和 `concerns.mentionedBy`，而默认的 v2 提示词不输出这两个字段（开启校验时，看到投票却没有 `pollReadings` 的 v2 答案会被判为不一致）；能输出它们的 v4 系列三版都没通过验收，所以计划中的 step 2（v4.x + 校验开启）没有跑。C35 在 v4.1 下 5/5 夸大 mentionedBy，正是它要抓的情况，留作以后评估。开启前还要先修回放截断（见 [round 4 待办](round4-todo.md) ①）。
